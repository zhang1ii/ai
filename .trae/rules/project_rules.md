# AI 工作手册 - 数据标注与测试流程

## 重要指令（必看）

当你在本项目中工作时，请严格遵循以下流程。

---

## 工作流程

### 第一步：检查当前环境

在执行任何任务前，先检查根目录下已有的项目文件夹：

```bash
ls -la /Users/zhang/Documents/trae_projects/ai
```

### 第二步：创建并启动新项目（如果是新会话/新测试）

如果这是一个新的测试会话，**必须**先创建一个新的项目文件夹并自动启动：

```bash
npm run new
```

这会自动完成以下操作：
1. 创建下一个序号的项目文件夹（auto-2, auto-3, auto-4...）
2. 自动安装后端依赖（server 目录）
3. 自动安装前端依赖（client 目录）
4. 自动启动后端服务（端口 3001）
5. 自动启动前端服务（端口 5173）

**注意**：永远不要在 auto-1 或 template/ 中进行测试修改。这些是模板和参考项目。

### 第三步：等待服务启动

脚本会自动启动服务，等待输出显示：
```
=== 项目已就绪 ===
项目: auto-N
后端: http://localhost:3001
前端: http://localhost:5173
```

此时用户可以直接在浏览器中打开 http://localhost:5173 进行评估。

### 第四步：执行测试任务

在 auto-N 目录中执行用户的测试请求，包括：
- 代码修改
- 功能开发
- Bug 修复
- 任何测试操作

**重要**：修改代码后，如果需要重新启动服务来验证更改，先停止当前运行的服务，然后在对应目录手动重启。

### 第五步：数据标注（如有需要）

如果需要记录测试结果或进行数据标注：
- 标注文件使用 `.jsonl` 或 `.json` 格式
- 文件可以放在当前项目目录（auto-N）中
- 这些文件会被 `.gitignore` 自动忽略，不会被提交

## 目录结构说明

```
ai/
├── .trae/rules/project_rules.md  ← 本文件：AI 工作规则（自动加载）
├── agent.md                       ← 同样的规则（手动参考）
├── package.json                   ← 根目录配置，包含 npm run new 命令
├── scripts/
│   └── create-project.js          ← 创建新项目的脚本（自动安装+启动）
├── template/                      ← 项目模板（只读，不要修改）
├── auto-1/                        ← 原始参考项目（只读，不要修改）
├── auto-2/                        ← 测试项目 2（可修改，服务自动启动）
├── auto-3/                        ← 测试项目 3（可修改，服务自动启动）
└── ...
```

---

## 严格遵守的规则

1. **template/ 和 auto-1/ 是只读的** - 永远不要修改这两个目录
2. **每次新测试必须创建新目录** - 运行 `npm run new` 而不是在旧目录中继续
3. **项目按序号递增** - auto-2 → auto-3 → auto-4...
4. **不要提交测试项目** - auto-N 目录已在 .gitignore 中
5. **标注数据不提交** - .jsonl, .json 标注文件不会被提交
6. **服务自动启动** - `npm run new` 会自动安装依赖并启动前后端

## 快速开始示例

场景：用户说"帮我测试一下新功能"

你的操作流程：
1. 检查当前目录结构
2. 运行 `npm run new` 创建 auto-3（假设当前最大是 auto-2）
3. 脚本自动安装依赖并启动服务（后端:3001，前端:5173）
4. 告知用户可以在 http://localhost:5173 查看并评估
5. 在 auto-3 中执行用户的测试请求
6. 如需标注，在 auto-3 中创建 .jsonl 文件

## 记住

- 一键就绪 = `npm run new` 完成创建+安装+启动
- 隔离测试 = 每个测试一个独立的 auto-N 文件夹
- 保持模板干净 = 不要修改 template/ 和 auto-1/
- 数据安全 = 标注文件自动被忽略，不会污染 Git
- 用户直接评估 = 服务启动后用户可以立即在浏览器中测试
